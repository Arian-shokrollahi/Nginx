# 2-worker_connections directive
# 2- توضیح برایه تعداد کانکشن هایی که میتونه هر پراسس کارگر داشته باشد
---
### 1-دایرکتیو worker_connections چیست و چیکار میکند؟
این دایرکتیو مشخص می‌کند که **هر یک عدد Worker Process** به طور همزمان توانایی باز نگه داشتن چند عدد کانکشن شبکه (شبکه TCP / درخواست‌های کاربر یا ارتباط با بک‌اند) را دارد.

---
## 2-### . محل قرارگیری در کانفیگ (Context)

برخلاف `worker_processes` که در Main Context قرار داشت، `worker_connections` **حتماً باید درون بلاک `events { }`** تعریف شود.
```bash
# فایل /etc/nginx/nginx.conf

worker_processes auto;

# بلاک رویدادها
events {
    # حداکثر کانکشن همزمان برای هر ورکر
    worker_connections 1024;
}

http {
    # سایر تنظیمات وب‌سرور...
}

```
- الان یه دوره ای بکنیم از فایل قبلی و الان -->مثال: اگر بخواهیم از nginx به عنوان reverse proxy استفاده کنیم و پردازنده ما 6 هسته داشته باشد چقدر کانکشن میتونه سرورمون داشته باشه؟
```bash
6 core-=>worker_processes
worker_connections = 1024
Max client if nginx as reverse proxy -->
worker_processes X worker_connections /2
---6x1024/2=3072 max client
```

| ویژگی                      | توضیحات                                                                  |
| -------------------------- | ------------------------------------------------------------------------ |
| **محل قرارگیری در کانفیگ** | درون بلاک `events { ... }`                                               |
| **مقادیر مجاز**            | یک عدد صحیح مثبت (معمولاً مثل `512`, `1024`, `2048`, `4096`, `8192`)     |
| **مقدار پیش‌فرض**          | `512` در برخی نسخه‌های خام یا `1024` در پکیج‌های استاندارد اوبونتو/دبیان |
| **پروسس هدف**              | تعیین سقف پذیرش کانکشن برای **هر Worker Process**                        |
