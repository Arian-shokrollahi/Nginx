# 1-worker and master process
---
## برای اینکه **Master Process** و **Worker Process** کاملاً جا بیفته، اول یک **مثال ساده از دنیای واقعی  می‌زنیم، بعد دقیقاً کارکرد فنی‌شون توی لینوکس** رو می‌بینیم.


---

### 1-مثال رستوران (دید مفهومی)

یک رستوران خیلی شلوغ رو تصور کن:

- **مدیر رستوران (Master Process):**
    
    - خودش غذا نمی‌پزه و سفارش از مشتری نمی‌گیره.
    - اول صبح درِ رستوران و انبار رو باز می‌کنه (پورت‌های شبکه رو باز می‌کنه).
    - چک می‌کنه منوی امروز چیه (فایل کانفیگ رو می‌خونه و تست می‌کنه).
    - گارسون‌ها و آشپزها رو استخدام و مدیریت می‌کنه (Workerها رو می‌سازه).
    - اگر یک گارسون غش کنه یا حالش بد بشه، سریع یکی دیگه رو می‌فرسته جاش (Self-healing).
    - وقتی شما منو رو تغییر می‌دی، میره به بچه‌ها میگه: «از این به بعد سفارش جدید این شکلیه!» (بدون اینکه مشتری‌های فعلی رو بیرون کنه).
- **گارسون‌ها و پرسنل (Worker Processes):**
    
    - کار واقعی و اصلی رستوران رو انجام میدن.
    - با مشتری‌ها سر و کار دارن: سفارش می‌گیرن (درخواست HTTP)، غذا تحویل میدن (فایل HTML یا عکس)، فاکتور میدن.
    - حق ندارن دست به کلید انبار اصلی بزنن یا منو رو عوض کنن (دسترسی محدود امنیتی دارن).

---
### 2-دید فنی در لینوکس (زیر کاپوت چه خبره؟)

وقتی دستور `ps aux | grep nginx` رو توی لینوکس بزنی، معمولاً همچین خروجی‌ای می‌بینی:
```bash
ps aux | grep nginx


USER       PID   PPID  COMMAND
root      1234      1  nginx: master process /usr/sbin/nginx
www-data  1235   1234  nginx: worker process
www-data  1236   1234  nginx: worker process

```

## به دو ستون **USER** و **PPID** (شناسه پروسس والد) دقت کن:
#### الف) Master Process  (با دسترسی `root`):
وقتی تو دستور `sudo systemctl start nginx` یا `sudo service nginx start` رو می‌زنی:

1. سیستم‌عامل (`systemd`) مستقیماً فایل باینری `/usr/sbin/nginx` رو اجرا می‌کنه.
2. این دستور در واقع **Master Process** رو بالا میاره.
3. بلافاصله اون مستر پروسس، فرزندان خودش یعنی **Worker Processها** رو درجا تولید (`fork`) می‌کنه.

4. **پورت‌های پایین (Privileged Ports):** توی سیستم‌عامل‌های لینوکسی، برای اینکه برنامه‌ای بتونه به پورت‌های زیر 1024 (مثل پورت `80` برای HTTP و `443` برای HTTPS) گوش بده، **حتماً نیاز به دسترسی کاربر root داره**. مستر پروسس با دسترسی root بالا میاد و این سوکت‌ها/پورت‌ها رو باز می‌کنه.
5. **بررسی کانفیگ (`nginx.conf`):** فایل کانفیگ رو می‌خونه. اگر سینتکس اشتباه باشه، اصلاً اجازه اجرا نمیده.
6. **مدیریت Workerها:** اگر شما سیستم چند هسته‌ای داشته باشی، به تعداد هسته‌ها ورکر تولید می‌کنه (`fork` می‌کنه). ورکرها بچه‌های مستر هستن (Parent-Child relation).
7. **Reload بدون Down-Time (Zero-downtime):** وقتی دستور `nginx -s reload` می‌زنی:
    - مستر کانفیگ جدید رو می‌خونه.
    - اگر درست بود، چند ورکر جدید با کانفیگ نو بالا میاره.
    - به ورکرهای قدیمی سیگنال میده که: «درخواست‌های فعلی‌تون رو تموم کنید و بعد خاموش بشید». در تمام این مدت، سرویس حتی ۱ ثانیه هم قطع نمیشه!

#### ب) Worker Process (با دسترسی محدود مثلاً `www-data` یا `nginx`):

1. **دریافت و پردازش ترافیک:** تمام کلاینت‌ها (مرورگرها، اپلیکیشن‌ها) که به سرور وصل میشن، مستقیماً با Worker صحبت می‌کنن.
2. **امنیت (Security Isolation):** اگر وب‌سایت هک بشه یا یک باگ در نرم‌افزار اکسپلویت بشه، نفوذگر فقط به دسترسی کاربر `www-data` می‌رسه نه `root`! چون کلاینت هیچ راه ارتباطی مستقیمی با Master Process نداره.
3. **مکانیزم Non-Blocking Event-Loop:**
    - هر ورکر یک حلقه (Loop) مبتنی بر `epoll` در کرنل لینوکس داره.
    - برای هر درخواست جدید یک Thread یا Process مجزا نمی‌سازه (برعکس وب‌سرورهای قدیمی).
    - برای همین یک عدد ورکر پروسس ساده می‌تونه با **چند مگابایت رم**، **۱۰ هزار کانکشن همزمان** رو بدون اینکه معطل فایل یا دیسک بشه، مدیریت کنه.

---

| ویژگی                  | Master Process                                   | Worker Process                                                  |
| ---------------------- | ------------------------------------------------ | --------------------------------------------------------------- |
| تعداد در سرور          | معمولاً فقط ۱ عدد                                | معمولاً به اندازه تعداد هسته‌های CPU                            |
| کاربر اجراکننده (User) | root                                             | www-data یا nginx؛ کاربر عادی و محدود                           |
| کاری که انجام می‌دهد   | مدیریت کانفیگ، باز کردن پورت‌ها و ساختن Workerها | خواندن فایل‌ها، ارسال پاسخ HTTP به کاربر و اتصال به دیتابیس/PHP |
| تماس با کلاینت؟        | خیر؛ درخواست‌ها را مستقیم پردازش نمی‌کند         | بله؛ درخواست‌های کلاینت را دریافت و پردازش می‌کند               |

```
               +-------------------+
               |   Master Process  |  (اجرا با دسترسی root / مدیریت کانفیگ)
               +---------+---------+
                         |
      +------------------+------------------+
      |                                     |
+-----v-------------+                 +-----v-------------+
|  Worker Process 1 |                 |  Worker Process 2 |  (اجرا با دسترسی محدود/www-data)
+-------------------+                 +-------------------+
  (هزاران کانکشن همزمان)               (هزاران کانکشن همزمان)

```
