# 1-worker process directive
# 1-تنظیم دایرکتیو worker processes

---
## دایرکتیو worker processes چیست؟
 - دایرکتیو `worker_processes` یکی از مهم‌ترین و حیاتی‌ترین تنظیمات عملکردی (Performance) در انجین‌ایکس است.

---

 - ### ۱. کاربرد و وظیفه

این دایرکتیو به Master Process می‌گوید که **چند عدد Worker Process** برای پردازش درخواست‌های کاربران ایجاد کند


---

- ### ۲. نحوه‌ی مقداردهی (Syntax)
```bash
# ۱. تنظیم خودکار (روش توصیه شده):
worker_processes auto;

# ۲. تنظیم دستی تعداد:
worker_processes 4;
```
---
## ۳. نکات فنی و پشت صحنه
- ا-<mark>1</mark>-**چرا `auto` بهترین گزینه‌است؟**

وقتی مقدار رو روی `auto` می‌گذاری، Nginx در زمان استارت، سیستم را اسکن کرده و تعداد هسته‌های پردازنده (CPU Cores) را شناسایی می‌کند و دقیقاً به همان تعداد ورکر می‌سازد.

- -ا-<mark>2فرمول محاسبه</mark> حداکثر کانکشن همزمان: حداکثر ظرفیت پذیرش درخواست همزمان سرور از ضرب این دایرکتیو در `worker_connections` به‌دست می‌آید:
```
Max clients = workder_processes X worker_connections
```

##### _مثال:_ اگر ۴ هسته CPU داشته باشید و `worker_connections 1024` باشد:
- کانکشن هایه همزمان --->4 تا worker_processes رو در 1024 ضرب میکنیم = 4096 کانکشن
- ا-<mark>ظرفیت کل سرور</mark> --->پس شد تعداد Worker_processes  ضرب در Worker_connections میشه ظرفیت کل سرور و کلاینت هایه شما

- ا-<mark>3</mark>-**چرا نباید تعداد را بیشتر از هسته‌های CPU بگذاریم؟**

چون ورکرها بر پایه Asynchronous Non-blocking Event-loop کار می‌کنند، یک ورکر روی یک هسته می‌تواند هزاران درخواست را هندل کند. اگر تعداد ورکرها را بیشتر از تعداد هسته‌ها بگذارید، CPU مجبور به **Context Switching** (جابه‌جایی مداوم بین پروسس‌ها) می‌شود که باعث افت سرعت و مصرف بیهوده منابع خواهد شد.

| ویژگی | توضیحات |
|---|---|
| **محل قرارگیری در کانفیگ** | Main Context (بالاترین سطح فایل nginx.conf) |
| **مقادیر مجاز** | یک عدد صحیح مثبت (مثل 1, 4, 8) یا کلمه کلیدی auto |
| **مقدار پیش‌فرض** | 1 |
| **پروسس هدف** | تعیین‌کننده تعداد Worker Processها |

# بریم سراغه نکات پایانی و دوره

### ۱. این عدد “به ازای هر ورکر” است

همون‌طور که گفتی، `worker_connections` حداکثر تعداد کانکشنی هست که **هر ورکر** می‌تونه باز نگه داره. بنابراین ظرفیت کل سرور شما برابر است با:

`worker_processes` × `worker_connections`

### ۲. نکته طلایی برای Reverse Proxy

ا<mark>گر از Nginx به عنوان واسط (Proxy) برای اپلیکیشن‌هایی مثل (Node.js, Python, PHP) استفاده می‌کنی، باید حواست باشه که هر درخواست کلاینت **دو تا** کانکشن مصرف می‌کنه:</mark> 

1. کانکشن بین **کلاینت و Nginx**.
2. کانکشن بین **Nginx و برنامه (Backend)**.

بنابراین اگر `worker_connections` رو روی ۱۰۲۴ گذاشتی، در حالت Proxy، عملاً نصف اون (یعنی ۵۱۲ تا) برای کلاینت‌های واقعی ظرفیت داری.

### ۳. محدودیت سیستم‌عامل (OS Limit)

حتی اگر در کانفیگ بنویسی ۱۰۰,۰۰۰، تا وقتی سیستم‌عامل لینوکس اجازه نده، Nginx نمی‌تونه اون تعداد کانکشن رو باز کنه. لینوکس فایلی به نام `ulimit` داره که حداکثر تعداد فایل‌های باز (هر کانکشن یک فایل است) رو کنترل می‌کنه.

## و اخرین نکته محل تنظیم این دایرکتیو در کجا است
## کجا؟ (محل تنظیم)

**فایل:** `/etc/nginx/nginx.conf` (در توزیع‌های Ubuntu، Debian و Kali)

**محل در فایل:** بالاترین سطح فایل (Main Context) — یعنی **بیرون** از بلاک‌های `events`، `http` و `server`.
```bash

# فایل: /etc/nginx/nginx.conf

user www-data;            # ← بیرون از بلاک‌ها
worker_processes auto;    # ← همین‌جا، خط بالا تنظیم می‌شود
pid /run/nginx.pid;       # ← بیرون از بلاک‌ها

events {
    worker_connections 1024;
}

http {
    # ...
}

```
