# 03-pid-directive
# دایرکتیو pid
---
## دایرکتیو `pid` در Nginx چیست؟

دایرکتیو `pid` مشخص می‌کند که Nginx شناسه پروسه یا همان **Process ID (PID)** پروسس اصلی یعنی **Master Process** را داخل چه فایلی در سیستم‌عامل لینوکس ذخیره کند.
-->شما برید در مسیر etc/nginx/nginx.conf/ یه cat  بگیرید اون عددی رو که نشون میده عدد شماره  master process رو نشون میده

---
### ۱. چرا Nginx به فایل PID نیاز دارد؟ (به زبان ساده - EL5)

وقتی لینوکس یک برنامه را اجرا می‌کند، به آن یک شماره یکتا (مثلاً `1234`) می‌دهد.

ابزارهایی مثل `systemctl reload nginx` یا اسکریپت‌های سیستمی برای اینکه بدانند باید به کدام پروسه سیگنال بفرستند (مثلاً برای reload بدون قطعی یا بستن نرم سرور)، این شماره را از داخل این فایل می‌خوانند

---
### ۲. محل قرارگیری در کانفیگ (Context)

این دایرکتیو در بالاترین سطح فایل کانفیگ یعنی **Main Context** تعریف می‌شود.
```bash
# فایل /etc/nginx/nginx.conf

# تعیین مسیر ذخیره PID مستر پروسس
pid /run/nginx.pid;

worker_processes auto;

events {
    worker_connections 1024;
}

http {
    # سایر کانفیگ‌ها...
}
```

---
### ۳. بررسی با دستورات لینوکسی

می‌توانی محتوای این فایل را ببینی و با خروجی دستور `ps` تطبیق دهی:
```bash
# خواندن PID مستر از فایل
cat /run/nginx.pid

# بررسی پروسس مستر در سیستم
ps aux | grep "nginx: master"
```
- 1-اگر شما برید درون این فایل cat بگیرید--> run/nginx.pid/
- 2- یه عددی رو به شما نشون میده
- 3-حالا اگر sudo service nginx start & sudo systemctl enable nginx رو بزنید و جلوتر توضیح میدم فرایندشو ولی اگر سرویس رو  فعال کنیم
- 4- و ps aux رو بزنیم اون عددی که در pid ا master process میزنه همون عددی است که درون مسیر run/nginx.pid/ تعریف شده

---
### ۴. جدول خلاصه دایرکتیو `pid`

| ویژگی | توضیحات |
|---|---|
| **محل قرارگیری در کانفیگ** | Main Context (بالاترین سطح فایل nginx.conf) |
| **سینتکس (Syntax)** | `pid /path/to/file.pid;` |
| **مقادیر مجاز** | مسیر معتبر فایلی در لینوکس (Absolute Path) |
| **مقدار پیش‌فرض معمول** | `/run/nginx.pid` یا `/var/run/nginx.pid` یا `logs/nginx.pid` |
| **پروسس هدف** | ذخیره شناسه پروسه فقط برای **Master Process** |
